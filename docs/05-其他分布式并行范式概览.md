# PyTorch 分布式训练（五）：除 DDP 数据并行之外，还有哪些范式？

**源码与 API 版本**：文中 API 与文档链接均以官方 **PyTorch 2.5.x** 为准；与 GitHub 标签 **[v2.5.0](https://github.com/pytorch/pytorch/releases/tag/v2.5.0)** 及 [PyTorch 2.5 文档](https://pytorch.org/docs/2.5/) 一致。

本篇是**索引级**总览：前几篇讲的 **`DistributedDataParallel`（DDP）** 属于最经典的 **数据并行**——**每 rank 一份完整模型副本**，用 **`all_reduce`** 把梯度对齐，再各自 `optimizer.step()`。工业界与大规模训练里还会遇到下面几类范式；它们在 **通信原语、内存占用、代码组织方式** 上与纯 DDP 不同，适合**单独成系列**逐篇展开。


## 1. 张量并行（Tensor Parallelism, TP）

**思想**：把**单层或一组层**内的矩阵乘拆到多张卡上，使每张卡只存参数与激活的一部分。单步前向/反向往往需要 **卡间高频、小粒度** 的通信（对 NVLink / 机内拓扑敏感）。  
**与 DDP 关系**：TP 解决「单层太大放不进一张卡」；DDP 解决「整模型能放进一张卡但要多卡扩 batch」。二者可组合，但通信模式完全不同。  
**PyTorch 侧线索**：生态中常见 Megatron-LM 风格实现；核心库中与 **distributed tensor / `DTensor`** 等相关的 API 以 [2.5 文档](https://pytorch.org/docs/2.5/) 与发行说明为准检索。


## 2. 流水线并行（Pipeline Parallelism, PP）

**思想**：把**网络按层或按 stage 切成多段**，不同 rank 负责不同段，micro-batch 在段间流水传递，以时间换空间（单 rank 只驻留部分层）。  
**关键代价**：**流水线气泡（bubble）**、调度（1F1B、interleaved 等）、**激活检查点**与显存权衡。  
**与 DDP 关系**：PP 解决「整模型太深/太大，单卡连一层都吃力或希望分层驻留」；通信形态常是 **点对点** 与阶段边界上的 **allgather** 等组合，而不是单纯「每步一次梯度 allreduce」。  
**PyTorch 侧线索**：历史上存在 **`torch.distributed.pipeline`** 等 API；具体可用形态以当前版本文档与教程为准。


## 3. 全分片数据并行（FSDP）与 ZeRO 系优化

**思想**：**参数、梯度、优化器状态**不必在每个进程上各存一份全量；可以 **分片（shard）** 到组内各 rank，前向/反向时通过 **`all_gather` / `reduce_scatter`** 等组合把当前计算需要的视图凑齐。  
**与 DDP 关系**：DDP 默认是「每 rank 全量模型 + allreduce 梯度」；FSDP / ZeRO 更关注 **显存曲线**，通信模式从「主要是梯度 allreduce」变为 **分片状态 + 按需聚合** 的组合。  
**文档入口**：[FullyShardedDataParallel (FSDP)](https://pytorch.org/docs/2.5/fsdp.html)。  
**补充**：`DistributedDataParallel` 文档亦提到可与 **`ZeroRedundancyOptimizer`** 搭配降低优化器状态占用（见 [DDP 文档](https://pytorch.org/docs/2.5/generated/torch.nn.parallel.DistributedDataParallel.html) 中的 `ZeroRedundancyOptimizer` 说明），属于另一类「只省优化器状态、模型仍各 rank 一份」的折中。


## 4. RPC 与分布式 autograd

**思想**：把算子或模块放到不同进程/机器上，通过 **RPC** 远程调用；与「每进程一份模型、每步集体 allreduce」的 SPMD 风格不同。  
**文档入口**：[Distributed RPC Framework](https://pytorch.org/docs/2.5/rpc.html)。若与 DDP 混用，需严格遵循官方关于 **`torch.distributed.autograd.backward`** 与 **`DistributedOptimizer`** 的说明（见 DDP 文档中的 RPC 相关 note）。


## 5. 各范式与 DDP 梯度 allreduce 的对照

| 范式 | 典型解决的问题 | 与 DDP 梯度 allreduce 的差异 |
|------|----------------|-------------------------------|
| DDP 数据并行 | 扩 batch、多机复现经典训练 | 以 **allreduce 梯度** 为主 |
| 张量并行 | 单层过大 | 层内切分，通信频繁 |
| 流水线并行 | 层数过深、单卡驻留 | 阶段式 P2P / 组合 collective |
| FSDP / ZeRO | 显存不够放全模型+状态 | **shard + all_gather / reduce_scatter** |
| RPC | 服务化、异构远程调用 | SPMD 假设弱 |

**DDP 基础系列**对应上表第一行；**TP / PP / FSDP / RPC** 可按上表拆成多篇独立技术文，分别对照官方文档与 **v2.5.0** 源码，避免把「FSDP 的 `reduce_scatter`」与「DDP 的梯度 `all_reduce`」混为同一机制描述。
